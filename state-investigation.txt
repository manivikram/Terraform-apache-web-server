TERRAFORM STATE INVESTIGATION
=============================

Project: Terraform Apache Web Server
Region: us-east-1

Purpose
-------
Terraform state keeps track of the relationship between the Terraform
configuration and the actual resources created in AWS.

1. List Resources Managed by Terraform
---------------------------------------

Command:

terraform state list

Expected resources:

module.web_server.aws_instance.web
module.web_server.aws_security_group.web

The EC2 instance and Security Group are both managed inside the reusable
ec2_web_server Terraform module.


2. Inspect EC2 Instance State
-----------------------------

Command:

terraform state show module.web_server.aws_instance.web

Deployed EC2 information:

Instance ID: i-0761149d8c537375f
Instance Type: t3.micro
Availability Zone: us-east-1c
Public IP: 52.23.198.226
Public DNS: ec2-52-23-198-226.compute-1.amazonaws.com

The EC2 instance is managed by:

module.web_server.aws_instance.web

The instance uses EC2 user data to automatically install Apache and create
the custom webpage during startup.


3. EC2 Security Configuration
------------------------------

The Terraform state shows that the EC2 instance uses:

IMDSv2:
http_tokens = "required"

Root EBS Volume:
encrypted = true
volume_type = "gp3"

These settings improve the security of the EC2 instance.


4. Inspect Security Group State
-------------------------------

Command:

terraform state show module.web_server.aws_security_group.web

Security Group ID:

sg-02b1a0ebcec592855

The Security Group allows:

Inbound:
TCP port 80 from 0.0.0.0/0

Outbound:
All outbound traffic

This allows users to access the Apache webpage over HTTP.


5. Terraform Outputs
--------------------

Command:

terraform output

Outputs from the deployment:

availability_zone = "us-east-1c"
instance_id = "i-0761149d8c537375f"
public_dns = "ec2-52-23-198-226.compute-1.amazonaws.com"
public_ip = "52.23.198.226"
security_group_id = "sg-02b1a0ebcec592855"
website_url = "http://52.23.198.226"


6. Verify Web Server
--------------------

Command:

curl http://52.23.198.226

The command returned the custom HTML page, confirming that:

- The EC2 instance was running.
- The Security Group allowed HTTP traffic.
- The user-data template executed successfully.
- Apache was installed and started.
- The custom webpage was deployed successfully.


7. Terraform State File
-----------------------

Terraform stores information about the deployed infrastructure in:

terraform.tfstate

The state file should not be committed to Git because it can contain
infrastructure details and potentially sensitive information.

The .gitignore file excludes:

.terraform/
*.tfstate
*.tfstate.*
crash.log


8. Destroy Resources
--------------------

After testing the infrastructure, resources can be removed using:

terraform destroy

Terraform uses the state file to determine which AWS resources belong
to this configuration and removes them.

After destruction, the following command can be used to verify that no
managed resources remain:

terraform state list


Conclusion
----------

Terraform successfully created and tracked an Apache web server using a
reusable Terraform module.

The reusable module manages both:

- AWS Security Group
- AWS EC2 instance

The deployment also uses an encrypted gp3 root volume, IMDSv2, automated
Apache installation, configurable webpage content, Terraform variables,
and Terraform outputs.
